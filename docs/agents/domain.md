# 领域文档

本文定义工程技能在探索和修改本仓库时，应如何使用领域文档。

## 探索前阅读

在文件存在时，阅读：

- 仓库根目录下的 `CONTEXT.md`。
- `docs/adr/` 下与当前工作相关的 ADR。

如果这些文件不存在，则静默继续，不创建占位文档。通常由 `grill-with-docs` 调用的 `domain-modeling`，会在术语或长期有效的决策真正形成时按需创建它们。

## 布局

本仓库使用单上下文布局：

```text
/
├── CONTEXT.md
├── docs/
│   └── adr/
└── src/
```

## 词汇

在 Issue 标题、规格、测试和实现讨论中，应始终使用 `CONTEXT.md` 定义的术语。

如果所需概念尚未记录，先确认项目中是否已经存在既定名称。如果确实存在领域词汇缺口，则通过 `domain-modeling` 记录。

## ADR 冲突

如果拟议工作与现有 ADR 冲突，应明确指出冲突，而不是静默覆盖已有决策。
